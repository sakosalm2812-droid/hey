# Dictation Vocabulary

Account-scoped dictation preferences now include a bounded `vocabulary` list of up to 32 phrases (80 characters each), alongside corrections and snippets. The combined corrections, snippets, and vocabulary limit is 64 entries per effective preference set. Global and per-app saves preserve an existing vocabulary when older callers omit the field; callers can clear it by explicitly saving an empty list.

`createDictationSession` accepts vocabulary and passes a frozen snapshot to the speech provider for that session. The browser adapter uses `SpeechRecognitionPhrase` contextual-biasing hints when that constructor is present and otherwise continues without hints. This API is experimental and browser/provider support varies; a hint does not guarantee recognition. See [MDN: SpeechRecognitionPhrase](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognitionPhrase) and [MDN: SpeechRecognition.phrases](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/phrases).

Corrections and snippet names still replace only whole Unicode phrases in one pass. Locale-aware duplicate checks reject corrections, snippet names, or vocabulary that collide within the effective global or per-app settings. The dictation runtime keeps transcript text in memory and only forwards it to its caller; it does not persist or submit transcripts. A caller must pass the loaded vocabulary snapshot into `createDictationSession`; no user-facing vocabulary editor or cross-app insertion is added by this runtime contract.
